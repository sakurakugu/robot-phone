# 手机端原生模块开发注意事项

本文档记录在 React Native 0.84 bridgeless 模式下开发原生模块（TurboModule）时踩过的坑，以及正确的实现方式。以 mDNS 发现模块（`SparkMdns`）为例。

---

## 背景：RN 0.84 bridgeless 模式的模块注册机制

`newArchEnabled=true` 时，React Native 使用 JSI（JavaScript Interface）直接调用原生方法，不再经过 Bridge。模块注册链如下：

```
JS: TurboModuleRegistry.get('SparkMdns')
  → C++ TurboModuleManager::getTurboModule()
    → JNI 回调 Java：getTurboJavaModule("SparkMdns")
      → ReactPackageTurboModuleManagerDelegate.getModule()
        → BaseReactPackage.getModule() → 创建 Java 模块实例
    → C++ 封装 InitParams { instance = Java 实例 }
    → DefaultTurboModuleManagerDelegate::javaModuleProvider()
      → REACT_NATIVE_APP_MODULE_PROVIDER → AppSpecs_ModuleProvider
        → new NativeSparkMdnsSpecJSI(params)  // JSI 包装
```

---

## 必须满足的两个条件

### 条件 1：必须有 Codegen 规范文件

**现象**：模块编译通过，APK 中存在对应 `.class` 文件，但运行时提示 `module not found` 或 `could not be found. Verify that a module by this name is registered in the native binary`。

**原因**：C++ 的 `javaModuleProvider`（位于 `node_modules/react-native/ReactAndroid/cmake-utils/default-app-setup/OnLoad.cpp`）只识别通过 Codegen 生成 C++ JSI 绑定的模块：

```cpp
// OnLoad.cpp
std::shared_ptr<TurboModule> javaModuleProvider(const std::string& name, ...) {
    // 仅以下三类模块会被处理：
    auto m = REACT_NATIVE_APP_MODULE_PROVIDER(name, params);  // ← Codegen 生成的应用模块
    if (m) return m;
    if (auto m = FBReactNativeSpec_ModuleProvider(name, params)) return m;  // ← RN 核心模块
    if (auto m = autolinking_ModuleProvider(name, params)) return m;       // ← autolink 的 npm 包
    return nullptr;
}
```

没有 Codegen 规范，`REACT_NATIVE_APP_MODULE_PROVIDER` 宏就不会被定义，模块对 C++ 完全不可见，无论 Java 侧如何注册都无效。

**解决方案**：

① 在 `package.json` 中添加 `codegenConfig`：

```json
{
  "codegenConfig": {
    "name": "AppSpecs",
    "type": "modules",
    "jsSrcsDir": "src",
    "android": {
      "javaPackageName": "com.sparkrobot.codegen"
    }
  }
}
```

② 创建 Codegen 规范文件（文件名**必须以 `Native` 开头**）：

```typescript
// src/shared/native/NativeSparkMdns.ts
import type { TurboModule } from "react-native";
import { TurboModuleRegistry } from "react-native";

export interface Spec extends TurboModule {
  scan(timeoutSeconds: number): Promise<Object[]>;
}

export default TurboModuleRegistry.getEnforcing<Spec>("SparkMdns");
```

③ Gradle 构建时会自动生成：

- `build/generated/source/codegen/java/com/sparkrobot/codegen/NativeSparkMdnsSpec.java`（Java 抽象类）
- `build/generated/source/codegen/jni/AppSpecs.h` + `AppSpecs-generated.cpp`（C++ JSI 绑定）

④ Android 原生模块类**必须继承生成的抽象类**：

```kotlin
// 正确：继承 Codegen 生成的抽象类
class MdnsModule(reactContext: ReactApplicationContext) :
    NativeSparkMdnsSpec(reactContext) {

    @ReactMethod
    override fun scan(timeoutSeconds: Double, promise: Promise) { ... }
}
```

⑤ `MdnsPackage` 中 `isTurboModule` 必须设为 `true`：

```kotlin
ReactModuleInfo(
    NativeSparkMdnsSpec.NAME,
    MdnsModule::class.java.name,
    false,  // canOverrideExistingModule
    false,  // needsEagerInit
    false,  // isCxxModule
    true,   // isTurboModule ← 必须为 true，否则 C++ 不会尝试创建 JSI 包装
)
```

---

### 条件 2：必须在 MainApplication.kt 中注册 Package

**现象**：编译通过，所有文件正确，但运行时日志中看不到 `MdnsPackage` 或 `MdnsModule` 的任何输出。

**原因**：`MainApplication.kt` 中的包列表没有实际调用 `add(MdnsPackage())`。

**正确写法**（`android/app/src/main/java/com/sparkrobot/MainApplication.kt`）：

```kotlin
import com.sparkrobot.mdns.MdnsPackage

override val reactHost: ReactHost by lazy {
    getDefaultReactHost(
        context = applicationContext,
        packageList = PackageList(this).packages.apply {
            add(MdnsPackage())  // ← 必须添加，否则模块完全不存在
        },
    )
}
```

## 完整文件清单

| 文件                                   | 作用                                         |
| -------------------------------------- | -------------------------------------------- |
| `package.json`                         | 添加 `codegenConfig`，触发 Codegen 构建      |
| `src/shared/native/NativeSparkMdns.ts` | Codegen 规范（定义 JS 接口 + 触发 C++ 生成） |
| `src/shared/native/SparkMdns.ts`       | JS 封装（直接 `import NativeSparkMdns`）     |
| `android/.../mdns/MdnsModule.kt`       | 继承 `NativeSparkMdnsSpec`，实现 `scan()`    |
| `android/.../mdns/MdnsPackage.kt`      | `BaseReactPackage`，`isTurboModule = true`   |
| `android/.../MainApplication.kt`       | `add(MdnsPackage())`                         |
| `ios/RobotPhone/MdnsModule.swift`      | iOS 实现（NetServiceBrowser）                |
| `ios/RobotPhone/MdnsModuleBridge.m`    | iOS ObjC 桥接                                |

## 调试方法

### 1. 确认 Codegen 产物是否生成

```
D:\.build\RobotPhone\app\generated\source\codegen\
  java/com/sparkrobot/codegen/NativeSparkMdnsSpec.java   ← 必须存在
  jni/AppSpecs.h                                         ← 必须存在
  jni/AppSpecs-generated.cpp                             ← 必须存在
```

### 2. 确认 CMake 编译标志

在 `D:\.build\RobotPhone\app\cxx\Debug\...\arm64-v8a\build.ninja` 中搜索：

```
REACT_NATIVE_APP_MODULE_PROVIDER=AppSpecs_ModuleProvider
```

如果存在，说明 C++ 绑定正确链接。

### 3. 通过日志验证加载

```
adb logcat | grep -E "SparkMdns|MdnsPackage|MdnsModule"
```

正常启动应看到：

```
MdnsPackage: getReactModuleInfoProvider called
MdnsPackage: getModule called with name=SparkMdns
MdnsPackage: Creating MdnsModule instance
MdnsModule:  MdnsModule created, name=SparkMdns
ReactNativeJS: [SparkMdns] module=true, platform=android
```

## mDNS 服务说明

机器狗端（`robot-agent`）通过 Python `zeroconf` 库注册 mDNS 服务：

- **服务类型**：`_sparkrobot._tcp.local.`
- **TXT Record 字段**：`uuid` / `name` / `model` / `version` / `ip` / `port`

手机端扫描超时建议设为 `3` 秒，扫描完成后通过 `syncDiscoveredRobots()` 对比本地已有机器人，相同 UUID 则更新 IP/名称等信息，新发现的则提示用户添加。
